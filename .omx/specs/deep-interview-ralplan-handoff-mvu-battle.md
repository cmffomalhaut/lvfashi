# Deep-Interview -> Ralplan Handoff Brief

## 1. 关键认知
- 本项目中的 MVU 不是泛泛的“状态对象讨论”，而是要最终落到 **MVU 变量结构脚本 / `schema.ts` / 变量结构注册脚本**。
- 因此后续规划必须把“MVU 字段设计”理解为：
  1. `schema.ts` 顶层与子结构设计
  2. 对应注册脚本与状态栏/store 访问方式
  3. message 级临时战斗数据与主卡牌常驻热状态的分层

## 2. 已完成的需求澄清
- 总体需求基线：`.omx/specs/deep-interview-docs-requirements-srs.md`
- 战斗流程与轻量战斗规则：`.omx/specs/deep-interview-battle-flow-p1.md`
- MVU 主骨架澄清已完成，可进入规划

## 3. MVU 主骨架（已确认）
### 主卡牌常驻热状态顶层
- `世界`
- `主角`
  - `当前化身`
  - `旅法师`
- `队伍`
- `敌方`
- `背包`
- `任务`
- `当前可见卡`

### 分层约束
- `battle_session` = **message 级临时战斗数据**
- `battle_session` **不是**主卡牌 MVU 常驻字段

### `当前化身`
至少包括：
- `id / 名称`
- `五维`
- `HP当前/上限`
- `MP当前/上限`
- `护盾量`
- `物攻 / 魔攻 / 物防 / 魔防`
- `技能列表`
- `状态效果`
- `装备`

### `旅法师`
至少包括：
- `当前火花阶段`
- `当前阶段进度`
- `已锚定位面`
- `已收录地印`
- `半位面总数`
- `已立界徽`
- `激活卡牌上限`
- `下一阶段`
- `下一阶段条件`
- `金钱`

### `队伍` / `敌方`
- 均为 `record by id`
- 值对象与 `当前化身` 基本同构
- `队伍` 只放当前在场队员
- `敌方` 为当前敌方集合

### `背包`
- `record by id`
- 每项至少：`名称 / 数量 / 标签 / 描述 / 效果`

### `任务`
- `record by id`
- 对象内保留任务名称

### `当前可见卡`
- `record by id`
- 每张卡至少：`名称 / id / 描述`
- 用于前端展示与 AI prompt 裁剪，避免整仓库泄漏

### `状态效果`
- 常驻
- 数组
- 每项最小字段：`名称 / 时间 / 描述`

### `技能列表`
- `record by id`
- 每项最小字段：`id / 名称 / 稀有度 / 标签 / 描述 / 消耗`

## 4. 规划时必须遵守的方向
1. 先做 **MVU schema / 变量结构脚本 / 状态栏-store 接入** 的规划，不要把 MVU 理解成抽象字段表就结束。
2. P0 先稳定主热状态与可见卡/仓库/回写安全。
3. P1 再接入战斗浮窗与 message 级 `battle_session`。
4. 规划中要明确：哪些字段属于 `schema.ts`，哪些属于 message 临时战斗态，哪些不该进入 MVU（如谱库条目全文）。

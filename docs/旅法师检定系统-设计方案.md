## 一、检定公式

### 1.1 属性修正值

标准 D&D 公式：`mod = floor((属性值 - 10) / 2)`

| 属性值 | 修正 | 属性值 | 修正 |
|:--:|:--:|:--:|:--:|
| 3 | -4 | 12 | +1 |
| 4 | -3 | 13 | +1 |
| 5 | -3 | 14 | +2 |
| 6 | -2 | 15 | +2 |
| 7 | -2 | 16 | +3 |
| 8 | -1 | 17 | +3 |
| 9 | -1 | 18 | +4 |
| 10 | 0 | | |
| 11 | 0 | | |

### 1.2 检定公式

```
d20 + 属性修正 + 熟练加值(可选) + 环境修正(可选) ≥ DC
```

- **d20**：骰子1~20，自然20=必定成功，自然1=必定失败
- **属性修正**：基于对应五维属性
- **熟练加值**：如果旅法师在该领域有优势（如感高者检定羁绊时 +1）
- **环境修正**：根据场景难度附加±1~±3

### 1.3 DC 难度参考

| 难度 | DC | 说明 |
|------|:--:|------|
| 琐碎 | 5 | 几乎一定成功 |
| 简单 | 10 | 普通人一半几率成功 |
| 中等 | 15 | 需要一定训练 |
| 困难 | 18 | 专家级 |
| 极难 | 22 | 需要非常高属性+运气 |
| 超凡 | 25 | 属性18+熟练也仅有小概率 |

## 二、检定在酒馆环境中的运作方式

核心问题：**谁裁定检定？**

第一版采用 **AI 主裁判 + 脚本骰子池**。

脚本不提供 `/检定` 命令，也不通过正则捕获 AI 文本后替 AI 投骰。日常和战斗中的检定都由 AI 根据当前属性、当前状态、当前可见卡、背包物品和本次骰子池自行裁定。

脚本职责：

1. 生成本次骰子池；
2. 临时注入当前 prompt；
3. 确保历史骰子池不进入后续 AI 上下文；
4. 对 AI 输出的变量更新做字段白名单和结构校验；
5. 不复算 AI 的检定结果。

### 2.1 骰子池注入

默认骰子池：

| 场景 | 骰子池 |
|------|--------|
| 日常主聊天 | d20 × 10 |
| 回合制战斗 | 每回合 d20 × 20 |
| 快速整场战斗 | d20 × 40 |

Prompt 注入格式：

```text
本轮骰子池（需要检定时按顺序使用，不需要则忽略）：
d20#1=14, d20#2=7, d20#3=19, d20#4=3, d20#5=11,
d20#6=5, d20#7=16, d20#8=2, d20#9=20, d20#10=9
```

AI 使用规则：

- 需要属性检定、随机事件、命中、抵抗、掉落等裁定时，按顺序取用骰子；
- 不需要检定时不要强行使用骰子；
- 骰子池不是剧情物品；
- 普通检定使用 `d20 + 属性修正 + 可解释加成 ≥ DC`；
- 戏剧性节点可以突破常规公式，但必须在叙事或分析中说明原因。

### 2.2 历史骰子池不发送

骰子池只属于本次生成。过去楼层中的骰子池必须掩盖掉，不发送给后续 AI。

实现要求：

- 日常骰子池优先只做 prompt 临时注入，不写入楼层正文；
- 如必须写入楼层，使用 `<DicePool>...</DicePool>` 包裹；
- 配置“不发送正则”移除历史 `<DicePool>...</DicePool>`；
- CombatLog 中如包含骰子记录，也必须随 CombatLog 一起从发送上下文移除。

### 2.3 检定结果展示

检定结果由 AI 直接写入叙事。脚本不追加独立检定结果楼层。

示例：

```text
你把巨力术压进肩臂，猛地撞上铁门。
d20#1=14 + 力量修正(+2) + 巨力术优势(+3) = 19，超过 DC15。
门闩在一声钝响里弯折，铁门向内撞开。
```

## 三、检定结果展示

### 3.1 toastr 通知

```
成功: "✅ 力量检定成功！d20(14) + 力(+2) = 16 ≥ DC15"
失败: "❌ 力量检定失败！d20(6) + 力(+2) = 8 < DC15"
暴击: "🎉 自然20！必定成功！"
大失败: "💀 自然1！必定失败！"
```

### 3.2 写入楼层

检定结果以系统消息形式追加到聊天：

```
[检定结果]
属性: 力量 | DC: 15 | 投掷: 14 + 修正(+2) = 16
结果: ✅ 成功
说明: 推开铁门
```

这样AI在后续回复中能读取这条消息，结合检定结果继续叙事。

## 四、酒馆环境下是否合适？

### 4.1 天然契合的点

| 特性 | 酒馆支撑 |
|------|---------|
| 属性值存在 MVU 变量中 | ✅ `getVariables` / `Mvu.getMvuData` 随时读取 |
| 检定结果需要写入变量（HP变化等） | ✅ `replaceVariables` / `Mvu.replaceMvuData` |
| 检定结果需要显示给玩家 | ✅ `toastr` + `createChatMessages` |
| 战斗检定自动触发 | ✅ 战斗引擎脚本控制流程 |
| 命令拦截 | ✅ `tavern_events.MESSAGE_RECEIVED` 监听 |
| AI输出文本检测 | ✅ `tavern_events.CHARACTER_MESSAGE_RENDERED` 监听 |
| AI知道检定规则 | ✅ 世界书条目定义规则 |

### 4.2 潜在问题和缓解

| 问题 | 缓解方案 |
|------|---------|
| AI滥用骰子池 | Prompt 中说明“不需要检定时忽略骰子池” |
| 历史骰子污染上下文 | 骰子池临时注入；历史 `<DicePool>` 用不发送正则移除 |
| AI裁定过于发散 | 变量更新白名单 + Zod 校验 + 玩家战斗结果确认/重试/放弃 |
| 长期资源膨胀 | 正式卡牌仓库、当前可见区、卡槽、永久属性等禁止 AI 直接修改 |
| 背包物品被 AI 擅自消耗 | 战斗中只有玩家策略明确点名的背包物品才能消耗 |
| 卡牌太多影响注意力 | AI 只看到当前可见区摘要，不看到聊天变量卡牌仓库 |

### 4.3 结论：合适，但需注意三点

1. **AI 是检定裁判** — AI 根据骰子池、属性、状态和可见卡直接裁定结果。
2. **脚本不是结算器** — 脚本只注入骰子池、保护变量结构、限制长期系统字段。
3. **历史骰子不进上下文** — 过去楼层的骰子池必须通过临时注入或不发送正则处理。

## 五、实现边界

第一版检定不使用脚本命令结算，也不在文档内维护 `check.ts` 源码。

脚本只负责：

- 在最新楼层注入本次可用骰子池；
- 在发送给 AI 前遮蔽历史 `<DicePool>...</DicePool>`；
- 必要时在状态栏展示本次骰子池或检定提示；
- 对 AI 输出的变量更新做白名单和结构校验。

检定裁定由 AI 根据叙事、属性、当前状态、卡牌摘要和骰子池完成。

## 六、世界书约束 AI 输出检定格式

在 `世界书/变量/变量更新规则.yaml` 末尾添加：

```yaml
$检定规则:
  content: |-
    当剧情需要属性检定（如力量检定推开铁门、感知检定察觉隐藏信息等）时：
    1. 在回复末尾使用格式 [检定:属性名 DC难度值 简短说明]
       属性名用：力/体/敏/智/感
       难度值参考：简单10 中等15 困难18 极难22
    2. 你的叙事中只描述情境和后果的可能性，不要预判检定结果
    3. 检定结果将由系统自动判定并追加到回复后
    4. 如果叙事中不需要检定，不要强行添加检定标记
```

## 七、检定在战斗中的使用

第一版战斗检定不由脚本调用 `doCheck()`。战斗 AI 根据战斗 prompt 中的属性、当前状态、当前可见卡、背包、玩家策略和骰子池自行裁定。

| 节点 | 检定 | 说明 |
|------|------|------|
| 伤害计算 | AI 裁定 | 可参考公式，但允许戏剧性节点突破并说明原因 |
| 暴击判断 | AI 使用骰子池裁定 | 使用本回合骰子池，不由脚本复算 |
| 逃跑 | AI 使用骰子池裁定 | 结合敏捷、场景、状态、玩家策略 |
| 掉落 | AI 裁定后写入背包 | 不直接写正式卡牌仓库 |
| Boss羁绊获取 | AI 裁定后可给出背包战利品或剧情结果 | 正式卡牌仍需玩家状态栏整理 |
| 非战斗技能检定 | AI 使用日常骰子池裁定 | 不需要 `/检定` 命令 |

## 八、关键设计决策总结

| 决策 | 选择 | 理由 |
|------|------|------|
| 谁裁定检定 | AI | 保留叙事自由度，支持仪式、伏击、场景优势等开放玩法 |
| 谁提供随机源 | 脚本 | 每次 prompt 注入骰子池，历史骰子不发送给 AI |
| 谁保护变量 | 脚本 | 字段白名单、Zod 校验、越界保护 |
| 日常检定触发 | AI 自行判断 | 根据属性、当前状态、可见卡、背包和骰子池裁定 |
| 战斗检定触发 | 战斗 AI 自行判断 | 玩家确认前可重试、换骰重试或放弃 |
| 正式卡牌奖励 | 状态栏整理 | AI 不能直接写卡牌仓库，奖励先进入背包 |

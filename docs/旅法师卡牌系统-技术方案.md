# 旅法师卡牌系统 — 核心设计方案 (v3)

> 基于酒馆助手 (Tavern Helper) + MVU 变量框架 + 酒馆 (SillyTavern) 的角色卡卡牌战斗系统
>
> 最后更新: 2026-05-25

---

## 一、设计总览

### 1.1 核心概念

```
主题：旅法师 (Planeswalker) 进入表里世界现代都市
核心：旅法师与NPC缔结羁绊，获取羁绊卡牌；击败怪物，获取掉落卡牌
队伍：旅法师化身 + 队友；第一版不设硬人数上限
世界：表世界（普通现代都市）+ 里世界（隐藏的超自然/怪物存在）
```

### 1.2 核心模型分层

```
┌──────────────────────────────────────────────────┐
│              聊天变量卡牌仓库（冷数据）              │
│  → 跟随当前聊天文件                                 │
│  → 保存完整正式卡牌                                 │
│  → AI 默认不可见                                    │
│  → 由状态栏查看、编辑、删除、加载                    │
├──────────────────────────────────────────────────┤
│              最新楼层 MVU（热状态）                  │
│  → 保存当前游戏状态                                 │
│  → 背包、任务、队伍、当前状态默认给 AI 看              │
│  → 当前可见卡只保存短摘要，不保存完整仓库              │
├──────────────────────────────────────────────────┤
│              当前可见区（Prompt 过滤器）              │
│  → 不是剧情装备锁定，也不是能力拥有上限                │
│  → 玩家随时通过状态栏更换（战斗中锁定）                │
│  → 控制哪些正式卡牌进入日常/战斗 prompt               │
├──────────────────────────────────────────────────┤
│              背包（剧情可见物品）                     │
│  → 放道具、材料、任务物、未整理卡材                    │
│  → 默认全量进入日常 prompt                            │
│  → 整理为正式卡牌时消耗对应背包物品                    │
└──────────────────────────────────────────────────┘
```

### 1.3 正式卡牌结构

正式卡牌存放在聊天变量仓库中。仓库不默认进入 prompt；只有玩家加入当前可见区后，脚本才把短摘要复制到最新楼层 MVU。

| 字段 | 说明 |
|------|------|
| `id` | 脚本生成的稳定 id，不使用名称作主键 |
| `类别` | `羁绊`、`技能`、`装备`、`地`、`道具` |
| `名称` | 可编辑显示名 |
| `稀有度` | `普通`、`稀有`、`史诗`、`传说` |
| `用途域` | 战斗、日常、探索、社交、仪式、召唤、收服、制作、移动、信息 |
| `标签` | 检索和筛选用 |
| `prompt策略` | 仅加载时注入、仅触发后注入、不自动注入 |
| `简介` | 状态栏快速查看 |
| `效果描述` | 仓库完整描述，可较长，不直接进 prompt |
| `日常摘要` | 进入日常 prompt 的短摘要 |
| `战斗摘要` | 进入战斗 prompt 的短摘要 |
| `触发条件` | 给 AI 和玩家参考 |
| `来源` | 获得楼层、获得方式、事件摘要 |
| `数值` | 可选辅助数值；AI 主裁判，不由脚本完整结算 |

整理方向第一版固定为：

| 方向 | 说明 |
|------|------|
| 战斗技能 | 主要进入战斗 prompt |
| 日常技能 | 主要进入日常、探索、社交 prompt |
| 仪式 | 可用于准备、场景布置、长期行动 |
| 装备 | 旅法师化身使用的武器、防具或装备能力 |
| 地牌 | 环境、领域、场景类效果 |
| 道具 | 可被加载为卡牌化道具 |
| 羁绊/召唤/收服 | NPC、宠物、灵体、羁绊关系或召唤能力 |

### 1.4 战斗实体结构

```
旅法师化身 / 敌人：
  名称, 等级, 经验值(非敌人),
  力, 体, 敏, 智, 感 (范围 3-18),
  HP, HP上限(仅敌人), MP,
  当前状态

队友：
  名称, 身份, 来历, 和玩家关系, 心声,
  等级, 经验值, 好感度,
  力, 体, 敏, 智, 感, HP, MP,
  2个主动技能, 1个被动技能,
  武器描述, 护甲描述
```

队友不使用卡牌仓库。队友装备和技能直接写在队友数据中，描述可以包含具体效果、加成、限制和风格。

队友入队时，主聊天 AI 根据剧情一次性生成完整队友资料：身份、来历、和玩家关系、心声、初始等级、初始经验值、好感度、五维、HP/MP、2 个主动技能、1 个被动技能、武器和护甲。脚本只校验格式和大致数值范围，不因队伍人数阻断写入，不负责替队友设计技能。

新队友创建时写入初始等级、经验值和五维，不视为成长结算；入队之后，队友等级、经验值和永久五维变化仍由脚本或玩家确认流程处理。

### 1.5 当前可见区

```
当前可见区是 prompt 预算和 AI 注意力过滤器。

仓库里可以有很多正式卡牌，但 AI 默认看不到。
玩家把卡牌加入当前可见区后，脚本复制短摘要到最新楼层 MVU。
日常 prompt 和战斗 prompt 再根据用途域筛选这些可见卡。
加载/卸载当前可见区不消耗剧情时间，不代表角色换装。
战斗开始后锁定当前可见区；要换卡必须放弃战斗并恢复战前状态。
```

默认提示限制（超限提示，不强制禁止）：

- 当前可见卡最多 12 张；
- 单张日常摘要 160 字；
- 单张战斗摘要 160 字；
- 日常 prompt 卡牌摘要总量 1200 字；
- 战斗 prompt 卡牌摘要总量 1200 字；
- 标签最多 12 个，每个 12 字；
- 效果描述 500 字，不直接进 prompt。

当前可见卡支持 `普通`、`优先`、`置顶` 三档优先级。超预算时优先保留置顶卡、强制可见卡、装备/当前状态相关卡、优先卡。

### 1.6 卡牌获取与整理

战斗、探索、剧情奖励先进入背包，作为 AI 可见的剧情物品、战利品、材料或未整理卡材。

玩家在状态栏选择背包物品并指定整理方向后：

1. 脚本读取背包物品和当前剧情摘要；
2. AI 输出结构化 JSON 卡牌草案；
3. 脚本用 Zod 校验和清洗；
4. 脚本生成稳定 `cardId`；
5. 正式卡牌写入聊天变量卡牌仓库；
6. 原背包物品数量 -1，归零则删除；
7. 整理失败时必须警告玩家，不写仓库、不消耗物品。

正式卡牌删除时，状态栏二次确认，并自动清理最新楼层 MVU 中所有对该 `cardId` 的引用；已经发生的当前状态不回滚，只保留来源文字。

### 1.7 数值系统

```
五维：力 体 敏 智 感  |  范围 3-18（DND式）
HP  = 体质 × 10 + 等级 × 2
MP  = (智力 + 感知) × 5 + 等级
属性修正 = floor((属性值 - 10) / 2)    (用于检定时加在 d20 上)
伤害公式 = 攻击力 × 倍率 - 防御力       (AI计算，脚本只限制明显越界和负数)
行动顺序 = 速度(敏属性)决定
经验值/等级：每级需要 100 × 当前等级 经验值，战斗后分配
```

### 1.8 检定系统（骰子池方案）

核心思路：**脚本预生成随机数 → 注入prompt → AI消费骰子做检定并叙事**

AI 是检定裁判。脚本不提供 `/检定` 命令，不在日常或战斗中复算检定结果。

每次生成 prompt 时，脚本注入本次骰子池。AI 需要检定时按顺序使用；不需要检定时忽略。

默认：

- 日常主聊天：d20 × 10；
- 回合制战斗：每回合 d20 × 20；
- 快速整场战斗：d20 × 40。

```
流程：
  脚本生成本次 d20 池
    → 临时注入本次 prompt
  AI读取 → 需要检定时取下一个骰子 → d20 + 属性修正 ≥ DC?
    → 叙事: "你猛地发力(d20#1=14 + 力+2 = 16 ≥ DC15)，铁门轰然推开"
  过去楼层中的 <DicePool>...</DicePool> 必须通过不发送正则移除
```

骰子池不写入长期 MVU。过去楼层的骰子池和 CombatLog 不进入后续 AI 上下文。

### 1.9 战斗系统

```
战斗界面：独立浮窗 UI（脚本 iframe 挂载到酒馆网页）
API 方式：优先使用 generateRaw / 自定义 API 配置；不优先裸 fetch
战斗模式：回合制（默认） / 快速整场战斗（可选）
战斗流程：玩家浮窗输入策略 → AI用骰子池裁定 → 玩家确认/重试/换骰重试/放弃
战斗 Prompt：骰子池 + 当前可见战斗卡摘要 + 背包 + 当前状态 + 我方阵容 + 敌方阵容 + 玩家策略
战斗中锁定当前可见区、仓库操作、背包整理
背包物品只有玩家策略明确点名时才允许使用/消耗
当前可见卡是否允许 AI 自由调用，由玩家在战斗前选择
脚本不复算战斗，只做变量白名单、结构校验、越界保护和战前快照恢复
```

### 1.10 战后处理

```
回合结果确认写回后：
  1. 脚本解析 AI 输出的 MVU 传统命令并实时更新最新楼层 MVU
  2. 更新战斗浮窗内的本场临时记录
  3. 不向主楼层追加 CombatLog

战斗最终胜利或失败并确认后：
  1. 完整战斗叙事追加到最新楼层末尾 <CombatLog>...</CombatLog>
  2. CombatLog 显示时折叠，发送给 AI 时通过正则移除
  3. 清空 stat_data.敌方
  4. 把一句胜败和核心结果写入 stat_data.世界.近期事务
  5. CombatLog 不包含任何变量更新命令

战斗未结束前关闭/放弃：
  恢复战前快照，不写 CombatLog，不写近期事务

掉落：
  默认进入背包；需要玩家之后在状态栏整理为正式卡牌

长休：玩家输入「长休」→ 恢复 HP/MP + 重置技能卡牌次数
```

### 1.11 日常形态

```
常驻状态栏五个大项：属性、背包、卡牌、队友、任务
战斗作为独立悬浮按钮/浮窗，不放进状态栏主 tab
面板使用 Vue + Pinia + TailwindCSS 前端界面
```

### 1.12 数据存储

```
聊天变量：
  旅法师卡牌仓库（完整正式卡牌，AI 默认不可见）

最新楼层 MVU stat_data：
  世界、任务、背包、队伍、当前状态、当前可见区、当前可见卡摘要、敌方、战斗状态

最新楼层正文：
  <CombatLog>完整战斗记录</CombatLog>
  显示折叠，发送 AI 时移除

战斗和日常 prompt：
  不扫描卡牌仓库
  只读取当前可见区摘要、背包、队伍、当前状态、任务和一条保底近期事务等热数据
```

## 二、关键规则补充

### 2.1 当前状态

`当前状态` 只记录正在生效的 buff、debuff、临时效果和场景效果。

字段保持简单：名称、目标、效果描述、来源。

AI 可以新增、修改、删除当前状态；状态栏也允许玩家手动编辑和删除。长休时脚本只提示是否清理临时状态，不自动清空全部状态。

### 2.2 背包

背包默认全量发送给 AI。第一版不做背包冷藏，也不自动隐藏背包物品。

玩家想起来就用，想不起来就算了。战斗中只有玩家策略明确点名的背包物品才能被使用或消耗。

### 2.3 HP/MP

脚本只负责防止 HP/MP 变成负数，并限制明显越界值。

HP 归零不自动死亡、不自动删档，也不自动施加固定长期惩罚。倒地、昏迷、战败、被俘、撤退、重伤等后果由 AI 按剧情裁定。

### 2.4 敌方数据

主聊天 AI 触发遭遇时写入 `敌方`。战斗浮窗读取当前 `敌方`。

战斗最终胜利或失败并确认后清空 `敌方`；放弃/关闭战斗时恢复战前快照。

### 2.5 队友离队

第一版不做自动离队归档。队友离队由玩家在状态栏手动删除。

如果剧情中 NPC 主动离开，主聊天 AI 可以叙事说明；是否删除 `队伍` 数据由玩家决定。

### 2.6 任务奖励

任务系统脚本不参与奖励结算。

奖励细则以后在世界书中单独确定。当前只规定：脚本不参与任务奖励结算；AI 可以按白名单写入背包、当前状态、任务状态或近期事务，但不能直接写卡牌仓库、经验、等级或永久属性。

需要变成正式卡牌的奖励，之后由玩家在状态栏从背包整理。

### 2.7 近期事务

`世界.近期事务` 是最多 1 条最近记录，用来保底衔接。

主要用途是战斗结束后记录胜败和关键结果，避免主聊天 AI 回到日常时不知道刚才是胜了还是败了。

它不是日志列表，不记录任务清单，不承担长期记忆。

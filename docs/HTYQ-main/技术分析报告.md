## 一、项目全景

| 属性 | 值 |
|---|---|
| **名称** | 🌐 活体引擎 (Living World Engine) |
| **类型** | SillyTavern 扩展 (extension) |
| **版本** | v1.5.0 |
| **入口** | `main.js` + `style.css`（由 `manifest.json` 注册） |
| **总量** | 30+ 文件，约 4500 行 JS |
| **许可证** | MIT |
| **核心定位** | 为酒馆角色扮演提供「世界后台推演」的面板 + 引擎系统 |
| **安装方式** | 复制到 SillyTavern 的 `plugins` 文件夹 |

### 功能清单

- 🌐 可拖拽地球悬浮球，点击展开活体引擎面板
- 📊 14 标签页面板：仪表/编年史/事件链/势力/关系/流言/经济/黑市/声誉/角色状态/因果链/外交事件/备忘/设置
- 🧠 LLM 驱动的世界推演引擎（支持自定义 API 或酒馆内置模型）
- 📚 世界书集成（自动导入角色绑定 + 全局世界书、手动选择条目）
- 🎲 11 个可开关 DLC 模块（恩怨录、黑市、经济脉搏、意外事件、声誉系统等）
- 📱 手机端自适应（面板全屏 + 下拉标签切换）
- 💾 localStorage 持久化，按聊天 ID 隔离存储

### 通信方式

所有模块通过 `window.HTYQ_XXX` 全局变量通信，不使用 ES Module 或 import：

```
main.js 串行加载（25 个文件，顺序由硬编码数组决定）
  ├─ 基础设施 → 确保 HTYQ_STATE / HTYQ_UTILS / HTYQ_RULES 先就绪
  ├─ UI 模块 → ui/*.js
  ├─ 设置子模块 → ui/settings/*.js
  └─ 引擎模块 → evolution/*.js
```

**⚠️ 关键细节：**

#### 3.6 `htyq-evolution-main.js` — 推演主控（189 行）

**推演入口：**
```javascript
async function runEvolution(manual = false) {
    if (isEvolving) return;              // 防重入锁
    if (!manual && !hasFirstResponse) return; // 首轮完成前不自动推演
    
    isEvolving = true;
    api.showPersistentToast('🌍 世界演化中...', false);
    try {
        const strategy = await ensureStrategy();
        await strategy.runWithStrategy(manual);
    } finally {
        isEvolving = false;
        api.hidePersistentToast();
    }
}
```

**绑定的酒馆事件：**
| 事件 | 处理函数 | 行为 |
|---|---|---|
| `message_received` | `onMessageReceived()` | 自动推演触发（受 `autoPollCounter` 控制） |
| `chat_loaded` | `onChatLoaded()` | 加载世界状态 + 同步世界书 + 可选注入 |
| `character_switched` | `onCharacterSwitched()` | 同步世界书 |

**自动推演频率控制：**
```javascript
function onMessageReceived() {
    if (settings.autoPollMode === 'auto') {
        autoPollCounter++;
        if (autoPollCounter >= settings.autoPollInterval) {
            autoPollCounter = 0;
            if (STATE.worldState.breaker <= 0)
                runEvolution(false);
            else
                STATE.worldState.breaker--;  // 跳过推演
        }
    }
}
```

### 4.4 重试机制

```javascript
const maxRetries = 3;
let currentRetry = 0;

async function attemptEvolution(manual) {
    try {
        // ... API 调用 + 解析 + 应用 ...
        currentRetry = 0;  // 成功后重置
    } catch (err) {
        if (currentRetry >= maxRetries) throw err;
        currentRetry++;
        showPersistentToast(`推演失败，第${currentRetry}/${maxRetries}次重试...`, true, 3000);
        await new Promise(r => setTimeout(r, 2000));
        return attemptEvolution(manual);  // 递归重试
    }
}

### 5.2 修复能力的边界

**✅ 能修复的 LLM 输出模式：**

| 模式 | 示例 | 修复后 |
|---|---|---|
| Markdown 代码块 | ` ```json {…} ``` ` | `{…}` |

**❌ 不能修复的模式（实际生产中常见）：**

| 问题 | 示例 | 后果 |
|---|---|---|
| JSON 被截断 | `{"world_digest": "京城今日发生` | JSON.parse 抛异常 |
| 单引号 | `{'world_digest': '...'}` | JSON.parse 抛异常 |
| 未引用 key | `{world_digest: "..."}` | JSON.parse 抛异常 |
| 尾随逗号 | `{"world_digest": "...",}` | JSON.parse 抛异常 |
| 注释 | `{"world_digest": "..." /* 注释 */}` | JSON.parse 抛异常 |
| 多重 JSON | `{…} {…}` | 只取第一个对象 |
| 布尔/数字引号 | `{"active": "true"}` | 类型错误，但不会崩溃 |
| 编码问题 | 中文乱码或特殊字符未转义 | JSON.parse 抛异常 |

### 5.3 失败后的恢复路径

```
JSON.parse 失败 或 applyEvolution 返回 false
    ↓
attemptEvolution() catch 捕获
    ↓
currentRetry < 3 → 等待 2s → 递归重试 attemptEvolution(manual)
currentRetry >= 3 → 抛出最终错误
    ↓
runEvolution() catch
    ↓
showFloatingWarning("推演彻底失败，请检查控制台或手动重试")
    ↓
isEvolving = false 解锁
    ↓
用户需要手动点击"手动推演"按钮重新开始
```

**⚠️ 注意：不存在增量修复。** 没有引入 `json5`、`safe-json-parse` 或任何自定义修复逻辑。所有错误都走重试路径。

│ 组件                                    │ 估算字符数   │
├─────────────────────────────────────────┼──────────────┤

├─────────────────────────────────────────┼──────────────┤

└─────────────────────────────────────────┴──────────────┘

**⚠️ 关键问题：** `max_tokens = 4000` 仅控制**输出长度**，输入 prompt 可能高达 35000 tokens。这意味着：
- 使用 4K/8K 上下文的模型时，prompt 会被静默截断
- 推荐使用 32K+ 上下文的模型
- 所有截断都是硬截断（`substring`），没有智能压缩

### 7.2 `entriesToText()` 序列化格式

```javascript
function entriesToText(entries) {
    let text = '';
    for (const entry of entries) {
        const title = entry.comment || entry.key?.join(', ') || '条目';
        const content = entry.content || '';
        text += `### ${title}\n${content}\n\n`;
    }
    return text.trim();
}
```

输出示例：
```
### 帝都长安概况
长安城分为内城和外城，内城为皇族和贵族居住区...

### 商业区
东市主要经营丝绸瓷器，西市为胡商聚集地，设有市舶司监管...
```

```

   → 演化上限：整个城市或多个顶级势力
   → 极值后果：全城通缉、不死不休

Lv.4 世界危机 → 刺杀君主、引发灭城
   → 演化上限：无限制

【特权修正（得罪了谁）】
- 受害者是核心人物/权贵 → Lv.1 自动跃升 Lv.2
- 受害者是顶级势力领袖 → 任何冒犯起步 Lv.3

## 十一、架构决策与风险矩阵

> 本节总结基于全部源码的分析，各决策对应的关键文件见前文各节文件引用。

### 11.1 关键设计决策与代价

| 决策 | 选择 | 好处 | 隐含代价 |
|---|---|---|---|
| 规则即代码 | 自然语言规则替代程序逻辑 | 灵活修改无需部署 | 行为不可预测、依赖 LLM 遵循能力 |
| 纯前端无后端 | 所有数据存 localStorage | 零运维、即装即用 | 清缓存丢数据、不能跨设备同步 |
| 全局 window 挂载 | 所有模块通过 window.HTYQ_XXX 通信 | 简单直接、无需构建工具 | 无模块隔离、命名冲突、依赖加载顺序 |
| 串行动态加载 | 25 个文件 in-order await | 依赖关系简单 | 加载失败需刷新、加载慢 |
| 全量 innerHTML 渲染 | 切标签全量重绘 | 实现简单 | 状态大时性能差、事件绑定反复注册 |
| 最小 JSON 修复 | 只去 ``` + {} 截取 | 代码量极少 | 常见格式错误直接崩溃 |
| 无回滚机制 | 分步推演失败不回滚 | 实现简化 | 数据可能处于不一致状态 |
| 无类型检查 | 纯 JS 无 TypeScript | 零构建成本 | 字段错误运行时才发现 |

### 11.2 风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| LLM 返回格式错误 | 高 | 高（推演失败） | 重试 3 次（不够强） |
| localStorage 数据丢失 | 中 | 高（全丢） | 导出功能（需手动） |
| Prompt 超过上下文窗口 | 高 | 高（推演质量下降） | 各种截断（硬截断不智能） |
| 分步推演部分失败 | 中 | 中（数据不一致） | 无缓解 |
| 加载顺序错误 | 低 | 高（完全不可用） | 加载器有 Promise 链（但无校验） |
| 模块命名冲突 | 低 | 中（功能异常） | 无缓解 |
| 推演性能问题 | 中 | 中（卡顿） | 防重入锁（只能阻塞不能优化） |

### 11.3 推荐改进方向（按优先级）

1. **JSON 解析加固** — 引入 `json5` 或自定义修复逻辑，支持单引号/无引号 key/尾随逗号
2. **推演进度可视化** — 分步策略下显示当前进度（"第 2/5 步：推演经济系统中..."）
3. **Token 预算自适应** — 根据当前状态大小动态调整截断阈值
4. **数据导出自动备份** — 在关键节点（世界重置、重大变更）自动触发 localStorage → JSON 文件导出
5. **错误回滚** — 分步推演用临时状态对象，全部成功后再写入
6. **类型层** — 核心数据结构用 JSDoc 注释或迁移 TypeScript

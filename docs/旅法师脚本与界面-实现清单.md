# 旅法师脚本与界面实现清单

> 本文是实现任务清单，不包含完整源码。
> 2026-05-25

---

## 一、技术路线

总体路线：先打通最小可运行闭环，再逐步加功能。不要先写完整战斗引擎；第一版的核心是数据存储、状态栏、prompt 过滤、AI 结果确认和回滚。

### 1.1 技术选型

| 模块 | 技术路线 |
|------|----------|
| MVU 数据结构 | TypeScript + Zod 4 定义 schema，注册到 MVU 变量框架 |
| 最新楼层状态 | 使用 `Mvu.getMvuData`、`Mvu.parseMessage`、`Mvu.replaceMvuData` 读写，目标固定为 `message_id: 'latest'` 或 `-1` |
| 聊天变量仓库 | 使用 `getVariables/replaceVariables({ type: 'chat' })` 保存完整卡牌仓库 |
| 状态栏 | 脚本项目创建独立 `createScriptIdIframe`，Vue + Pinia + `defineMvuDataStore(Schema, { type: 'message', message_id: 'latest' })` |
| 战斗浮窗 | 同一个脚本或独立脚本创建 `createScriptIdIframe` 浮窗，不放进状态栏主 tab |
| AI 调用 | 优先 `generateRaw` 或用户配置的自定义 API；不优先裸 `fetch` |
| 数据校验 | Zod 清洗结构，白名单过滤 AI 变量更新，HP/MP 做非负保护 |
| 上下文遮蔽 | 普通主聊天用酒馆正则遮蔽；脚本自建 `generateRaw` prompt 时手动移除历史 `<DicePool>...</DicePool>` 和 `<CombatLog>...</CombatLog>` |

必须遵守的酒馆助手约束：

- 所有 MVU 操作前先 `await waitGlobalInitialized('Mvu')`；
- 状态栏操作的是最新楼层，不使用楼层前端模板默认的 `getCurrentMessageId()` 作为目标；
- 如果最新楼层暂时没有 `stat_data`，状态栏应禁用写入并提示，或等待最新 MVU 楼层初始化完成；
- `generate` / `generateRaw` 自行请求 AI 不会自动解析 MVU 命令，必须手动 `Mvu.parseMessage`，再 `Mvu.replaceMvuData`；
- `Mvu.parseMessage` 没有解析到变量更新时可能没有可写结果，写回前必须做空值保护；
- 脚本挂载到酒馆页面主体时 Tailwind 样式不会自动生效；本方案的状态栏和战斗浮窗都使用独立 iframe，因此可继续使用前端样式。

### 1.2 纵向闭环顺序

第一条纵向闭环只做“能存、能看、能改、能回写”：

1. 建立 MVU schema 和注册脚本；
2. 做脚本挂载的状态栏基础壳，能读取最新楼层 MVU；
3. 实现属性、背包、任务、队友、当前状态的基础展示和编辑；
4. 实现聊天变量卡牌仓库读写；
5. 实现当前可见区：从仓库加载卡牌摘要到最新楼层 MVU；
6. 构建日常 prompt 热数据：背包、任务、队伍、当前状态、当前可见卡摘要、近期事务；
7. 加入变量更新白名单和结构校验；
8. 验证一次主聊天 AI 更新能被正确解析、过滤、写回。

第二条纵向闭环做“背包整理成卡牌”：

1. 背包物品选择；
2. 整理方向选择；
3. AI 生成卡牌 JSON 草案；
4. Zod 校验和清洗；
5. 写入聊天变量卡牌仓库；
6. 消耗背包物品；
7. 任一步失败则整包回滚并提示玩家。

第三条纵向闭环做“战斗最小闭环”：

1. 主聊天 AI 写入 `敌方`；
2. 玩家打开战斗浮窗；
3. 保存最新楼层战前快照，锁定当前可见区、仓库操作和背包整理；
4. 生成本回合骰子池并构建战斗 prompt；
5. AI 返回战斗预览；
6. 玩家确认、重试、换骰重试或放弃；
7. 确认后只写回 MVU 和浮窗临时记录；
8. 最终胜利或失败时，才写入完整 `CombatLog`、清空 `敌方`、覆盖 `世界.近期事务`、解锁状态栏。

### 1.3 模块边界

| 模块 | 负责 | 不负责 |
|------|------|--------|
| MVU schema | 字段结构、默认值、基础类型约束 | 游戏裁定 |
| 变量白名单 | 拒绝 AI 越权更新 | 判断剧情是否合理 |
| 卡牌仓库 | 冷数据保存、编辑、删除、搜索 | 默认发送给 AI |
| 当前可见区 | prompt 过滤和摘要复制 | 限制角色实际拥有能力 |
| 背包 | AI 可见物品和未整理卡材 | token 冷藏 |
| 卡牌整理 | JSON 校验、写仓库、消耗物品 | 保证 AI 设计强度绝对平衡 |
| 战斗浮窗 | 交互、快照、确认、重试、写回 | 复算 AI 战斗 |
| CombatLog | 最终战斗记录展示 | 变量命令承载 |

### 1.4 验证重点

实现时优先验证这些风险点：

- 仓库卡牌不在 prompt 中泄漏；
- 只有当前可见卡摘要进入 prompt；
- 历史骰子池和历史 CombatLog 不发送给 AI；
- 卡牌整理失败不会消耗背包物品；
- 战斗放弃/关闭能恢复战前快照；
- 战斗中途确认不会写主楼层 CombatLog；
- 战斗最终确认会清空 `敌方` 并覆盖 `世界.近期事务`；
- AI 试图修改卡牌仓库、当前可见区、等级、经验、永久五维时会被拒绝并提示；
- HP/MP 不会写成负数；
- 队友加入不会因为人数被脚本拦截。

### 1.5 可行性校验结论

按 `.cursor/rules/*.mdc` 和 `@types` 接口对照后，当前路线可以在酒馆助手里落地，但需要遵守下面的实现修正：

| 设计点 | 校验结论 | 实现要求 |
|--------|----------|----------|
| 聊天变量卡牌仓库 | 可行 | 使用 `getVariables/replaceVariables({ type: 'chat' })`，不写入 MVU，不自动进 prompt |
| 最新楼层 MVU | 可行 | 使用 `message_id: 'latest'` 或 `-1`，不要绑定状态栏所在旧楼层 |
| 状态栏常驻操作 | 可行但不能按普通楼层前端做 | 用脚本创建独立 iframe；状态栏 store 指向最新楼层 |
| 战斗浮窗 | 可行 | 用 `createScriptIdIframe`，在 iframe 内挂 Vue；关闭时卸载 |
| AI 战斗请求 | 可行 | 用 `generateRaw`/自定义 API；返回后必须手动 `Mvu.parseMessage` |
| 战斗变量写回 | 可行 | `parseMessage` 得到新 MVU 后再 `replaceMvuData` 写回最新楼层 |
| CombatLog 追加到最新楼层 | 可行 | 用 `getChatMessages(-1)` + `setChatMessages` 修改最新楼层正文 |
| 历史 CombatLog/DicePool 不发给 AI | 可行 | 普通聊天依赖 prompt-only 酒馆正则；脚本自建 prompt 时手动 strip |
| CombatLog 折叠显示 | 可行 | 用 display-only 酒馆正则或楼层渲染增强；不影响 prompt 遮蔽 |
| 背包整理失败回滚 | 可行 | 先生成和校验完整结果，再一次性写仓库和背包 |

不采用的路线：

- 不把状态栏做成只绑定 `getCurrentMessageId()` 的普通楼层前端，否则旧楼层状态栏会改错楼层；
- 不用 STScript 命令作为主要实现方式，优先用酒馆助手 `@types` 接口；
- 不靠脚本完整复算战斗，脚本只做数据保护和写回；
- 不把完整卡牌仓库放进 MVU 或世界书变量列表。

- 当前可见区管理；
- 背包管理；

## 三、状态栏

状态栏五个主项：

| 主项 | 功能 |
|------|------|
| 属性 | 化身五维、HP/MP、等级/经验、当前可见卡快捷入口 |
| 背包 | 查看、编辑、删除背包物品；整理为正式卡牌 |
| 卡牌 | 查看仓库、搜索、筛选、编辑、删除、加入/移出当前可见区、设置优先级 |
| 队友 | 查看和编辑队友资料、技能、装备、好感、心声；手动删除离队队友 |
| 任务 | 查看和编辑任务名称、状态、描述、来源、相关地点、相关人物 |

破坏性操作必须二次确认：

- 删除正式卡牌；
- 删除背包物品；
- 删除队友；
- 消耗背包物品；
- 清空或批量修改仓库。

非破坏性编辑允许玩家直接保存。超长文本只提示，不硬禁。

## 四、卡牌整理流程

流程：

1. 玩家在背包选择物品；
2. 玩家选择整理方向；
3. AI 根据背包物品和当前剧情生成卡牌 JSON 草案；
4. 脚本用 Zod 校验和清洗；
5. 脚本生成稳定 cardId；
6. 写入聊天变量卡牌仓库；
7. 消耗对应背包物品；
8. 失败时整包回滚，提示玩家。

整理方向：

- 战斗技能；
- 日常技能；
- 仪式；
- 装备；
- 地牌；
- 道具；
- 羁绊/召唤/收服。

---

## 五、战斗浮窗

战斗是独立悬浮按钮/浮窗，不放进状态栏主 tab。

打开浮窗时：

- 保存战前快照；
- 锁定当前可见区；
- 锁定仓库操作；
- 锁定背包整理；
- 允许玩家选择回合制或快速整场战斗；
- 默认回合制；
- 允许玩家选择 AI 是否可以自由调用当前可见卡。

每次 AI 返回战斗结果后，先进入预览态。

预览按钮：

- 确认写回；
- 重试，复用同一骰子池；
- 换骰重试，重新生成骰子池；
- 放弃，恢复战前快照。

战斗未结束前关闭浮窗，按放弃处理，恢复战前快照。

---

## 六、战斗写回

玩家确认回合结果后：

- 解析 AI 输出的 MVU 更新；
- 检查变量白名单；
- 检查结构合法性；
- 限制 HP/MP 不为负数；
- 实时写入最新楼层 MVU；
- 如果战斗尚未结束，只更新战斗浮窗内的本场临时记录；
- 如果战斗最终胜利或失败，把纯叙事追加到最新楼层末尾 `<CombatLog>...</CombatLog>`；
- 战斗最终结束时清空 `敌方`；
- 战斗最终结束时用一句胜败和核心结果覆盖 `世界.近期事务`；
- 战斗最终结束时解锁状态栏相关操作。

`CombatLog` 不包含变量更新命令。发送给 AI 前必须用正则遮蔽。

---

## 七、骰子池

脚本生成骰子池并临时注入 prompt。

- 日常：`d20 × 10`；
- 回合战斗：`d20 × 20`；
- 快速战斗：`d20 × 40`。

历史骰子池发送给 AI 前必须遮蔽。骰子池只服务本次 prompt，不写入长期 MVU。

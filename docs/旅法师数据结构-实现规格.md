# 旅法师数据结构实现规格

> 本文只记录数据结构、可见性和校验边界，不维护脚本源码。
> 2026-05-25

---

## 一、数据分层

| 层级 | 存放内容 | 是否默认发送给 AI |
|------|----------|-------------------|
| 聊天变量 | 完整正式卡牌仓库 | 否 |
| 最新楼层 MVU | 当前游戏热状态 | 是，按 prompt 类型筛选 |
| 楼层正文 | `<CombatLog>...</CombatLog>` 等显示文本 | 发送前用正则遮蔽 |

正式卡牌仓库跟随当前聊天文件。仓库里可以保存大量卡牌，但 prompt 构建器不扫描仓库；只有玩家把卡牌加入当前可见区，脚本才把短摘要复制进最新楼层 MVU。

---

## 二、最新楼层 MVU

第一版 `stat_data` 只保留热数据：

| 字段 | 类型/内容 | 规则 |
|------|-----------|------|
| `世界.当前时间` | 字符串 | 主聊天 AI 可按剧情推进 |
| `世界.当前地点` | 字符串 | 场景切换时更新 |
| `世界.近期事务` | 字符串 | 最多 1 条最近记录，保底用，通常由战斗结果或关键近况覆盖 |
| `化身` | 名称、HP/MP、等级/经验、五维 | 成长和升级不由 AI 直接结算 |
| `背包` | 道具、材料、战利品、任务物品、未整理卡材 | 默认全量发送给 AI；第一版不做仓库隐藏 |
| `任务` | 任务目标清单 | 只记录目标和状态，不自动结算奖励 |
| `队伍` | 队友列表，不设硬人数上限 | 队友不使用卡牌仓库 |
| `当前状态` | buff/debuff/临时效果 | 简单效果描述表，不做复杂状态引擎 |
| `当前可见区` | 当前加载卡牌 id、优先级等 | 只由状态栏脚本修改 |
| `当前可见卡摘要` | 加载卡牌的日常/战斗摘要 | 由脚本从仓库复制 |
| `敌方` | 当前遭遇敌人 | 遭遇时写入，战斗结束后清空 |

---

## 三、卡牌仓库

正式卡牌字段：

| 字段 | 说明 |
|------|------|
| `id` | 脚本生成稳定 id，不使用名称作主键 |
| `类别` | `羁绊`、`技能`、`装备`、`仪式`、`道具`、`召唤` |
| `名称` | 可编辑显示名 |
| `稀有度` | `普通`、`稀有`、`史诗`、`传说` |
| `用途域` | `战斗`、`日常`、`探索`、`社交`、`仪式`、`召唤`、`收服`、`制作`、`移动`、`信息` |
| `标签` | 检索和筛选用 |
| `prompt策略` | `仅加载时注入`、`仅触发后注入`、`不自动注入` |
| `简介` | 状态栏快速查看 |
| `效果描述` | 仓库完整描述，不直接进 prompt |
| `日常摘要` | 日常 prompt 使用的短摘要 |
| `战斗摘要` | 战斗 prompt 使用的短摘要 |
| `触发条件` | 给 AI 和玩家参考 |
| `来源` | 获得楼层、获得方式、事件摘要 |

长度限制只提示，不强制禁止保存。默认提示值：

- 当前可见卡最多 12 张；
- 单张日常摘要 160 字；
- 单张战斗摘要 160 字；
- prompt 卡牌摘要总量 1200 字；
- 标签最多 12 个，每个 12 字；
- 效果描述 500 字。

---

## 四、背包

背包是 AI 可见的剧情物品层，第一版不做冷藏。

背包物品可以是：

- 道具；
- 材料；
- 战利品；
- 任务物品；
- 未整理卡材。

战斗、探索、剧情奖励可以按世界书要求进入背包。玩家之后可在状态栏把背包物品整理成正式卡牌。整理成功后写入聊天变量卡牌仓库，并消耗对应背包物品；整理失败时不写仓库、不消耗物品，并提示玩家。

战斗中背包物品只有玩家策略明确点名时才能使用或消耗。

---

## 五、队友

队伍不设硬人数上限。队友不走卡牌仓库，技能和装备直接写在队友数据里。

队友字段：

- 名称；
- 身份；
- 来历；
- 和玩家关系；
- 心声；
- 初始等级、初始经验；
- 好感度；
- 力、体、敏、智、感；
- 当前 HP、当前 MP；
- 2 个主动技能；
- 1 个被动技能；
- 武器；
- 护甲。

入队规则：

- 玩家邀请且对方接受，或 NPC 主动加入时，主聊天 AI 可以直接写入 `队伍`；
- 新队友资料由主聊天 AI 按剧情一次性生成；
- 脚本只校验字段完整、稳定 id、数值范围；
- 离队第一版不做自动流程，由玩家在状态栏手动删除。

---

## 六、当前状态

`当前状态` 是简单 buff/debuff/临时效果表，不是事实日志。

字段：

- 名称；
- 目标；
- 效果描述；
- 来源。

主聊天 AI 和战斗 AI 可以新增、修改、删除当前状态。状态栏也允许玩家手动编辑和删除。

长休时不自动清空全部状态。脚本可以提示玩家是否清理临时状态，但诅咒、契约、长期环境影响等状态不能被长休默认移除。

---

## 七、HP/MP 与敌方生命周期

脚本只负责把 HP/MP 限制在合法范围内：

- HP 不低于 0；
- MP 不低于 0；
- 当前值不超过可计算或记录的上限。

HP 归零不自动死亡、不自动删档，也不自动施加长期惩罚。倒地、昏迷、战败、被俘、撤退、重伤等后果由 AI 按剧情裁定。

敌方生命周期：

1. 主聊天 AI 触发遭遇时写入 `敌方`；
2. 玩家打开战斗浮窗后，战斗使用当前 `敌方`；
3. 战斗最终确认结束后清空 `敌方`；
4. 放弃/关闭战斗时恢复战前快照。

---

## 八、近期事务

`世界.近期事务` 是一条最近记录，不是日志列表。

用途：

- 战斗结束后保底记录胜败和最关键结果；
- 防止主聊天 AI 回到日常时不知道刚才战斗是胜了还是败了；
- 在关键剧情切换后给 AI 一个最低限度近况。

规则：

- 最多 1 条；
- 可为空；
- 新记录覆盖旧记录；
- 不记录任务清单；
- 不替代任务系统；
- 不承担长期记忆功能。

## 1. 当前目标背景

我当前正在做的不是一个普通独立前端项目，而是：

- 运行在 Tavern Helper + MVU 生态中的前端/脚本系统
- 核心战斗数据来自消息楼层变量中的 `stat_data`
- 会用 AI 先分析完整 `stat_data`，找出正式战斗需要的字段
- 玩家可以勾选和修正这些字段
- 正式战斗时只发送这些抽出来的字段，而不是整个 `stat_data`
- AI 负责：
  - 字段分析
  - 单回合战斗推演
  - 快速整场战斗推演
  - 战利品检定 / 掉落结算
- 前端负责：
  - 设置页
  - API / Key / 模型配置
  - prompt 配置
  - 字段勾选树
  - 抽取 `selected_data`
  - 接收 AI 返回结果
  - 把 AI 返回的“路径 -> 新值”按路径写回 MVU

当前关键边界：

- 不让 AI 直接操作 MVU
- 不让 AI 返回 `add/remove/op`
- AI 只返回结构化结果
- 前端负责真正的路径写回

所以这次查看参考项目时，**你最应该判断的是设置系统、prompt 管理、字段/变量管理、AI 请求封装、响应后处理这些部分是否值得参考。**

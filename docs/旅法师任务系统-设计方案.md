# 任务系统设计方案

> 旅法师卡牌系统的轻量任务子系统
> 2026-05-25

---

## 一、定位

任务系统用于记录玩家明确接下、正在追踪或已经完成的目标。

它和 `世界.近期事务` 分开：

- `世界.近期事务`：最多 1 条最近记录，作为保底衔接使用。
- `任务`：给玩家和 AI 的目标清单，记录接下来要做什么、任务状态是什么。

任务不是完整任务引擎。第一版只做轻量记录和状态栏展示，不做自动寻路、自动完成判定、复杂阶段树或奖励结算。

---

## 二、数据结构

任务数据放在最新楼层 MVU `stat_data.任务` 中，默认进入日常 prompt。

```typescript
任务: {
  [任务id: string]: {
    名称: string;
    状态: '进行中' | '已完成' | '失败' | '搁置';
    描述: string;
    来源: string;
    相关地点: string;
    相关人物: string[];
  };
}
```

推荐 Zod 结构：

```typescript
任务: z.record(
  z.string().describe('任务id'),
  z.object({
    名称: z.string(),
    状态: z.enum(['进行中', '已完成', '失败', '搁置']).prefault('进行中'),
    描述: z.string().prefault(''),
    来源: z.string().prefault(''),
    相关地点: z.string().prefault(''),
    相关人物: z.array(z.string()).prefault([]),
  }),
).prefault({}),
```

任务 id 由脚本生成，不使用任务名称作为主键。任务名称可以在状态栏编辑，不影响引用。

---

## 三、字段说明

| 字段 | 说明 |
|------|------|
| 名称 | 玩家看到的任务标题 |
| 状态 | 当前任务状态：进行中、已完成、失败、搁置 |
| 描述 | 任务目标和已知要求，用短文本描述 |
| 来源 | 任务来自谁、什么事件或什么地点 |
| 相关地点 | 当前最相关地点 |
| 相关人物 | 与任务相关的人物名称列表 |

第一版不设置硬长度限制。状态栏可以在文本过长时提示，但不强制禁止保存。

---

## 四、AI 更新规则

日常 AI 可以更新任务字段；如果同一段剧情同时触发新队友加入，则按队伍更新规则另写 `队伍`，不要把队伍变化塞进任务字段。离队只写叙事，是否删除队友数据由玩家在状态栏手动决定。

允许：

- 新增任务；
- 更新任务描述；
- 修改任务状态；
- 补充相关地点、相关人物；
- 将任务标记为完成、失败或搁置。

禁止：

- 修改卡牌仓库；
- 修改当前可见区；
- 修改卡牌加载/槽位；
- 修改卡槽上限；
- 修改 `$flag` 系统控制字段。

任务系统脚本不参与奖励结算。奖励细则以后在世界书中单独确定；当前只规定 AI 可以按变量白名单写入允许字段。

任务字段本身不自动执行奖励、属性变化或队伍变化。

如果任务剧情中玩家邀请且对方接受，或 NPC 主动加入，主聊天 AI 可以在同次回复中直接写入最新楼层 MVU 的 `队伍`。这属于剧情确认后的队伍更新，不属于任务字段自动结算。新队友入队时由主聊天 AI 一次性生成初始等级、初始经验、五维、HP/MP、2 个主动技能、1 个被动技能、武器、护甲和背景关系字段。脚本只校验字段完整性、稳定 id 和数值范围，不因队伍人数阻断写入；校验失败时拒绝写入并提示玩家。离队数据不由 AI 自动删除，玩家在状态栏手动删除。

任务导致的永久属性变化、经验和等级变化不能由 AI 直接修改。AI 可以在任务描述中记录“任务完成后可能获得训练机会”；如确实需要最低限度近况，也可以覆盖 `世界.近期事务` 这一条保底短句。物品、材料、任务物品等可以按世界书限制进入背包；需要变成正式卡牌时，玩家之后在状态栏从背包整理。

## 五、状态栏展示

状态栏中单独提供「任务」大项。

第一版展示：

- 当前时间；
- 当前地点；
- 任务列表；
- 任务状态；
- 任务描述；
- 来源；
- 相关地点；
- 相关人物；
- `世界.近期事务` 的只读/编辑入口，最多 1 条保底短句。

任务和近期事务在同一页面可以相邻展示，但数据结构必须分开。

---

## 六、与近期事务的关系

任务记录目标，近期事务只记录 1 条最近近况。它主要作为保底衔接，尤其是战斗结束后记录胜败和关键结果，避免主聊天 AI 回到日常时误判刚才的战斗结果。

示例：

```typescript
任务: {
  quest_120_abcd: {
    名称: '调查第七码头的镜面异常',
    状态: '进行中',
    描述: '午夜前往旧城区第七码头，确认镜面异常是否与镜骨兽有关。',
    来源: '白川巡查员的委托',
    相关地点: '旧城区第七码头',
    相关人物: ['白川巡查员'],
  },
}

世界: {
  近期事务: '刚在旧城区第七码头经历战斗，白川委托仍待回报。',
}
```

如果任务完成，任务状态改为 `已完成`；近期事务最多只保留一句保底近况，不替代任务状态，也不承担任务记录功能。

---

## 七、第一版不做的事

第一版不做：

- 多阶段任务树；
- 自动任务奖励；
- 自动寻路；
- 任务优先级；
- 任务过期计时；
- 复杂任务依赖；
- 任务和卡牌仓库的自动联动。

这些以后可以扩展，但不进入第一版实现要求。
